Install#

pip install pianistpy

PIANISTpy needs Python 3.11 or later and runs on Linux, macOS and Windows.

The test suite is installed with the package. To run it on an installation:

pip install "pianistpy[test]"
pytest --pyargs pianistpy

CPU and GPU#

The package runs on the CPU everywhere and uses a GPU where the installed JAX supports one, with no setting to make. JAX’s CUDA builds are for Linux: on Windows the GPU is reached through the Windows Subsystem for Linux (or a Linux virtual machine) with the Linux wheels, and a native Windows Python runs the CPU-only mode. A GPU and a CPU give results that differ at rounding on the kernels; the accuracy goal holds on both, and each file records the backend that made it. To force one or the other, see Runtime options.

Only the main process uses the GPU: the worker processes of the observables’ pools run on the CPU. A GPU in the Exclusive_Process compute mode (nvidia-smi --query-gpu=compute_mode --format=csv shows it), common on shared clusters, serves one process, so where another process already holds it the package cannot reach it, and JAX’s error begins Unable to initialize backend 'cuda'. Free the GPU, share it through an MPS daemon (nvidia-cuda-mps-control -d), or run in the CPU-only mode.

A GPU speeds up the particle sampler and nothing else: the sampler’s speed table and the draw. The DF’s Poisson solve runs on the CPU on every platform: it is a serial ODE, and on a GPU each step would pay about a millisecond of launch latency, 50 to 200 times the CPU’s wall-clock time. The rows of the line-of-sight velocity table run in the worker pool on the CPU whatever the platform, and reading a built table takes the CPU’s wall-clock time.

Gray cells: the stage’s core runs on the CPU on every platform (the Poisson solve in rows 2 and 3, the table’s rows in the worker pool in row 6), and the number is the stage’s wall-clock time with the GPU present. On the model, sigma_r and sigma_t each run the model’s moments solve, and sigma_los and sigma_los_aperture each run that solve and the projection; nothing is kept on the model between calls, so each row is the cost of one call. The aperture rows from the table time a later call on the same aperture. The first call on a new aperture also finds the distribution function’s extrema at the radii the table has not met, once per aperture, and the first aperture call on a table starts its worker pool: on the Threadripper’s CPU the first call took 31.0 s.

On the Core Ultra 9 185H the table’s build (row 6) takes about five times the Threadripper’s wall-clock time. The rows on the model run the moments solve serially on one core, and there the wall-clock time of identical calls differs by up to half from one call to the next, so no ratio between the machines is given for them.
