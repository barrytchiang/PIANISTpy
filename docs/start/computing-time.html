Representative computing time#

The tables below give the computing time of each step of one PIANISTpy workflow, from a density profile to the observables. The example truncates an isotropic NFW halo by Method I. Method II then builds a model with a constant velocity anisotropy of 0.2 on the truncated density of that Method I model (Truncation in phase space). Each time in the tables is the time of a repeated call. The first call of a session takes longer due to JAX compilation, as does the first aperture call on a table (14.7 s on spock’s CPU). The times were measured with the default settings on two machines. The first machine is the spock GPU cluster of NTU CALab (PI: Hsi-Yu Schive), with an AMD Ryzen Threadripper PRO 5975WX CPU (32 cores, Linux) and an NVIDIA GeForce RTX 3080 Ti GPU. The second machine is a laptop with an Intel Core Ultra 9 185H CPU (16 cores, Windows 11). The steps that run in parallel processes used 28 processes on spock and 12 processes on the laptop, set by set_cores().

† A LosTable is built once per model, and every later call given the same LosTable reads it without a rebuild. Every observable in the table “Observables from the line-of-sight table” reads a LosTable. losvd and aperture_losvd called on a model build a LosTable first. Each row of a LosTable is the line-of-sight velocity distribution at one projected radius. The integral of each row agrees with the surface density, and the second moment of each row agrees with the projected dispersion, each to a relative error of at most \(10^{-6}\). For a distribution read between two rows, the estimated error is at most \(10^{-8}\) relative in the second moment, and at most \(10^{-7}\) of the row’s largest value at each velocity. A GPU-accelerated build, and builds of only the part of a LosTable that a call needs, are listed on the Upcoming features page.
